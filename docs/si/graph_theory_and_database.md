# Graph Theory සහ Graph Database මුල සිට සරලව (Neo4j)

මෙම ලේඛනය මඟින් "ග්‍රාෆ් න්‍යාය" (Graph Theory) යනු කුමක්ද යන්නත්, අපගේ පද්ධතියේ දත්ත ගබඩා කිරීමට සාමාන්‍ය Database එකකට අමතරව **Neo4j** කියන Graph Database එක භාවිතා කළේ ඇයිද යන්නත් සරලව පැහැදිලි කරයි.

---

## 1. Graph Theory (ග්‍රාෆ් න්‍යාය) කියන්නේ මොකක්ද?

ගණිතයේදී "Graph" එකක් කිව්වාම අපිට මතක් වෙන්නේ X සහ Y අක්ෂ තියෙන ප්‍රස්ථාරයක්. හැබැයි පරිගණක විද්‍යාවේදී (Computer Science) "Graph" එකක් කියන්නේ සම්පූර්ණයෙන්ම වෙනස් දෙයක්.

සරලවම කිව්වොත්, Graph එකක් කියන්නේ **තිත් (Nodes/Vertices)** සහ ඒ තිත් යා කරන **ඉරි (Edges/Relationships)** ගොඩකටයි. 

**හොඳම උදාහරණය: ෆේස්බුක් (Facebook)**
* ෆේස්බුක් එකේ ඉන්න හැම මනුස්සයෙක්ම එක "තිතක්" (Node එකක්).
* මම ඔයාගේ යාළුවෙක් නම්, මගෙයි ඔයාගෙයි තිත් දෙක යා කරලා "යාළුවෝ" කියලා "ඉරක්" (Relationship එකක්) අඳිනවා.

මේ විදිහට දේවල් අතර තියෙන **සම්බන්ධතාවලට (Relationships)** මුල් තැන දීලා හදන දැලකට (Network එකකට) අපි Graph එකක් කියලා කියනවා.

---

## 2. සාමාන්‍ය Database එකකුයි (PostgreSQL) Graph Database එකකුයි (Neo4j) අතර වෙනස

අපේ පද්ධතියේ සාමාන්‍ය දත්ත (උදා: ළමයින්ගේ නම්, විභාග ලකුණු, පැමිණීම) ගබඩා කරන්නේ **PostgreSQL** කියන සාමාන්‍ය දත්ත සමුදායක (Relational Database). සාමාන්‍ය Database එකක් හරියට Excel Sheet එකක් වගේ. වගු (Tables) තියෙනවා, පේළි (Rows) තියෙනවා.

**හැබැයි ප්‍රශ්නය එන්නේ සම්බන්ධතා හොයන්න ගියාමයි.**
හිතන්න ගණිතය විෂයේ පාඩම් 100ක් තියෙනවා කියලා. ඒ පාඩම් එකිනෙකට සම්බන්ධයි.
* "බෙදීම" ඉගෙනගන්න නම් ඊට කලින් "ගුණ කිරීම" පුළුවන් වෙන්න ඕනේ. (ගුණ කිරීම ➡️ බෙදීම)
* "ගුණ කිරීම" ඉගෙනගන්න නම් "එකතු කිරීම" පුළුවන් වෙන්න ඕනේ. (එකතු කිරීම ➡️ ගුණ කිරීම)

සාමාන්‍ය Excel Sheet එකක් වගේ Database (SQL) එකකින්, *"මේ ළමයාට භාග ගණන් හදන්න බැරි වෙන්න මුල්ම හේතුව මොකක්ද?"* කියලා හොයන්න ගියොත්, ඒක හොයන එක පරිගණකයට හරිම අමාරුයි. මොකද එකින් එකට සම්බන්ධතා හොයමින් වගුවෙන් වගුවට පනින්න ඕනේ (SQL Joins). මේකට ගොඩක් වෙලා යනවා.

**Graph Database එකක (Neo4j) මේක හරිම ලේසියි!**
Graph Database එකක් දත්ත ගබඩා කරන්නේම අර මුලින් කිව්ව "තිත් සහ ඉරි" (Nodes & Relationships) විදිහටමයි.

උදාහරණයක් විදිහට පද්ධතියේ දත්ත ගබඩා වෙන්නේ මෙහෙමයි:
`(ළමයා) ─[දන්නවා]─> (බෙදීම) ─[අවශ්‍යයි]─> (ගුණ කිරීම)`

මේ නිසා පරිගණකයට එක තිතකින් තව තිතකට පැන පැන (Path traversal) ඉතා වේගයෙන් සම්බන්ධතා හොයාගෙන යන්න පුළුවන්.

## 3. අපේ පද්ධතියට Neo4j (Graph Database) එකක් භාවිතා කළේ ඇයි?

සාමාන්‍ය PostgreSQL එකක් තියෙද්දිත් අපි Neo4j භාවිතා කළේ පද්ධතියේ තිබෙන විශේෂිත ගැටලු 3ක් විසඳගන්නයි.

### හේතුව 1: අධ්‍යාපනික සහාය එන්ජිම (Academic Support) - "ප්‍රශ්නයේ මුල සෙවීම"
ළමයෙක් විභාගයකින් අඩු ලකුණු ගත්තාම, ඒ ළමයාට උදව් කරන්න නම් අපි හොයාගන්න ඕනේ ළමයාට **මඟහැරුණු මුල්ම පාඩම (Root Concept / Prerequisite)** මොකක්ද කියලා. 
Neo4j වල ඇති අනුප්‍රාප්තික ප්‍රස්ථාරය (Prerequisite Graph) හරහා, පද්ධතියට පුළුවන් එක තත්පරයෙන් මුල්ම පාඩම දක්වා ආපස්සට ගිහින් (Traverse කරලා) *"මේ ළමයාට මුලින්ම එකතු කිරීම ආයෙත් කියලා දෙන්න"* කියලා ගුරුවරයාට යෝජනා කරන්න.

### හේතුව 2: අවදානම් සාධක එකිනෙක බැඳී ඇති ආකාරය (Causal Routes) පෙන්වීම
අපි කලින් කතා කරපු Bayesian Network එකේ තියෙන හේතු-ඵල ජාලය (ഉදා: දුප්පත්කම ➡️ ප්‍රවාහන ප්‍රශ්න ➡️ පාසල් නොපැමිණීම) ගුරුවරයාට ලස්සනට තිරයේ පෙන්වන්න (Visualize කරන්න) Neo4j උදව් වෙනවා. ගුරුවරයාට පුළුවන් ළමයාගේ අවදානමට බලපෑ මුල් හේතුව (Root cause) දක්වා ඊතල දිගේ ගිහින් බලන්න.

### හේතුව 3: පාසලේ පොදු ප්‍රශ්න (Shared Conditions) සහ මිතුරන් (Peer Ties) සෙවීම
ළමයින් ගොඩකට එකම ප්‍රශ්නයක් (උදා: ප්‍රවාහන ප්‍රශ්නයක්) තියෙනවා නම්, ඒක ළමයින්ගේ ප්‍රශ්නයක් නෙවෙයි මුළු පාසලේම ප්‍රශ්නයක්. Graph Database එකක් හරහා *"එකම ප්‍රශ්නයකට සම්බන්ධ වී ඇති ළමයි කවුද?"* කියලා ඉතා වේගයෙන් හොයාගන්න පුළුවන්. ඒ වගේම ළමයි අතර තියෙන මිත්‍ර සම්බන්ධතා (Friends with) සෙවීමටද මෙය ඉතා පහසුයි.

---

### සාරාංශය

අපි දත්ත ගබඩා කරන්න **PostgreSQL** භාවිතා කරන අතරේම, **Neo4j** භාවිතා කරන්නේ දත්ත අතර තියෙන **සම්බන්ධතා (Relationships)** ඉතා වේගයෙන් හොයාගෙන, ළමයෙකුගේ ප්‍රශ්නයක **"මුල (Root Cause)"** පහසුවෙන් ගුරුවරයාට පෙන්වා දීමටයි.
