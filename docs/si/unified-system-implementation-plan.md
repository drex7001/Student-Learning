# ඒකාබද්ධ පද්ධති ක්‍රියාත්මක කිරීමේ සැලැස්ම (Unified System Implementation Plan)

> **තත්ත්වය: ක්‍රියාත්මක කර ඇත.** අදියර හයම සම්පූර්ණ කර පරීක්ෂා කර ඇත. මෙම ලේඛනය සැලසුම් වාර්තාවක් ලෙස තබා ඇත — එන්ජින් දෙක එකතු කිරීමේ (merge) පසුබිම සහ ප්‍රතික්ෂේප කළ විකල්ප මොනවාද යන්න මෙහි දැක්වේ. පද්ධතිය දැන් ක්‍රියාත්මක වන ආකාරය සඳහා `docs/si/architecture.md` කියවන්න.

පාසල් හැරයාමේ අවදානම ගණනය කරන **Bayesian network** (`Risk/`) සහ **O/L ඉගෙනුම් බුද්ධි වේදිකාව** (`api/` + `web/`) එකම යෙදුමකට සම්බන්ධ කිරීම: *ශ්‍රී ලාංකීය පාසල් සඳහා AI මත පදනම් වූ ශිෂ්‍ය සුභසාධන නිරීක්ෂණ පද්ධතිය*.

---

## 1. සන්දර්භය (Context)

### මෙම වෙනස ඇයි? (Why this change)

මීට පෙර එකිනෙකට වෙනස් මූලාකෘති (Prototypes) දෙකක් පැවතුණි:
- එකකින් O/L විෂයයන්ගේ පූර්ව අවශ්‍යතා (prerequisite) රෝග විනිශ්චය සහ ප්‍රශ්නාවලි (quizzes) කළේය.
- අනෙකෙන් Bayesian Network භාවිතයෙන් ඊළඟ වාරයේදී ළමයෙකු පාසල් හැර යාමේ අවදානම ගණනය කළේය.

මෙම ව්‍යාපෘතිය මඟින් එම එන්ජින් දෙකම එකම Dashboard එකකට ගෙන එයි. ගුරුවරුන්ට, සිසුන්ට සහ උපදේශකයන්ට එකම තැනකින් තමන්ට අදාළ තොරතුරු බලාගත හැක.

### SHAP වෙනුවට Bayesian Network යොදාගැනීම

යෝජනාවෙහි (Proposal) මුලින් SHAP තාක්ෂණය භාවිතා කිරීමට යෝජනා කර තිබුණද, අපි ඒ වෙනුවට **Bayesian-network queries** භාවිතා කරමු. එය දුර්වල කිරීමක් නොව ඊට වඩා ප්‍රබල කිරීමකි:
- Random Forest + SHAP කියන්නේ හුදෙක් සම්බන්ධතා (Association) පෙන්වීමක් පමණි.
- Bayesian Graph/BN කියන්නේ "කුමක් කළොත්ද අවදානම අඩුවෙන්නේ?" (`do()` interventions) හරියටම ගණනය කළ හැකි Causal (හේතු-ඵල) තාක්ෂණයකි.

## 2. ඉලක්කගත ව්‍යුහය (Target architecture)

FastAPI සේවාව එක් API එකක් ලෙස ක්‍රියාත්මක වේ. වෙනම Microservices නොමැත. Postgres ප්‍රධාන දත්ත සඳහාත්, Neo4j සම්බන්ධතා සඳහාත් භාවිතා වේ. Next.js 16 මඟින් Frontend එක ධාවනය වේ. `pgmpy` සහ අනෙකුත් Python libraries සියල්ල එකම පරිසරයක (venv) ධාවනය වේ.

## 3. අදියර සැලැස්ම (Phase plan)

මෙය අදියර 6කින් යුතුව ගොඩනගා ඇත.

### අදියර 0 — කේත ගබඩාව හැඩගැස්වීම (Repository reshape)
Bayesian Network එන්ජිම API පැකේජය තුළට ගෙන ආ අතර, පර්යේෂණ වාර්තා `research/` ෆෝල්ඩරයේ තබා ගන්නා ලදී. `pgmpy` සහ `networkx` එකතු කර `shap` ඉවත් කරන ලදී.

### අදියර 1 — දත්ත ආකෘතිය: තාත්වික ශ්‍රී ලාංකීය පාසල් (Realistic Sri Lankan Data)
PostgreSQL හි පාසල්, පන්ති, සිසුන්, ගුරුවරුන් සඳහා වගු (Tables) සැකසීම. 
කොළඹ (නාගරික), බදුල්ල (ග්‍රාමීය), නුවරඑළිය (වතු) ලෙස සැබෑ අත්දැකීම ලබා දීම සඳහා කෘතිම සිසුන් 240කගේ දත්ත ජනනය කිරීම.

### අදියර 2 — අවදානම් සේවාව (The risk service - Highest priority)
Bayesian Network එන්ජිම API Endpoints බවට පත් කිරීම.
මෙහිදී ප්‍රධාන ගණනය කිරීම් (Estimands) 4ක් සකසා ඇත:
1. `drivers` - අවදානම වැඩි වීමට බලපෑ සාධක
2. `action_candidates` - උදව් කළ හැකි ක්‍රියාමාර්ග සහ ඒ හරහා අවදානම අඩුවන ප්‍රතිශතය
3. `worth_asking` - තවදුරටත් ගුරුවරයා විසින් සොයාබැලිය යුතු සාධක
4. `circumstance_gap` - පැමිණීමේ ලේඛනයේ සටහන් වීමටත් පෙරම අවදානමක් ඇති ළමයින් සෙවීම

**සදාචාරාත්මක නීති කේතයෙන්ම තහවුරු කිරීම:** වෙනස් කළ නොහැකි සාධක (උදා: Neuro_Type) වෙනස් කිරීමට (Intervene) උත්සාහ කළහොත් API එකින් HTTP 403 දෝෂයක් ලබා දෙයි. සිසුන්ට අවදානම් ලකුණු කිසිවිටෙකත් නොපෙන්වයි.

### අදියර 3 — සම්බන්ධතා සඳහා Neo4j (Neo4j as connection layer)
විෂය කරුණු අතර පූර්ව අවශ්‍යතා සෙවීමට, එකම අවදානමක් ඇති ළමයින් සෙවීමට, සහ ළමයින් අතර ඇති මිතුරු සබඳතා සෙවීමට (Graph traversal) Neo4j යොදාගැනීම.

### අදියර 4 — සත්‍යාපනය සහ භූමිකා (Authentication and roles)
ගුරුවරුන්ට සහ සිසුන්ට වෙනම පිවිසුම් සෑදීම. JWT Cookies හරහා ආරක්ෂාව තහවුරු කිරීම සහ `/internal/` මාර්ග Admin වරුන්ට පමණක් සීමා කිරීම.

### අදියර 5 — UI නැවත සැකසීම (UI rebuild)
Tailwind v4 සහ Next.js App Router භාවිතයෙන් අතුරුමුහුණත සැකසීම. මෙහිදී "හොඳයි" කියා පෙන්වීමට කොළ පාට භාවිත කිරීමෙන් වැළකී ඇත, මන්ද කිසිදු දරුවෙකුව ලේබල් නොකරන බැවිනි. සියලුම ප්‍රස්ථාර (Graphs) එකම ආකාරයකට පෙන්වීම.

### අදියර 6 — දැනුම්දීම් සහ වාර්තා (Alerts and reports)
ගුරුවරුන්ට ඇලර්ට් (Notifications) ලැබෙන පද්ධතියක් සැකසීම සහ උපදේශකවරුන් සඳහා මුද්‍රණය කළ හැකි වාර්තා (Printable Case Summaries) සැකසීම.

---

## 4. පරීක්ෂා කිරීම (Verification)

API හි ඇති පරීක්ෂණ 206 (Tests) මඟින් පද්ධතිය නිවැරදිව ක්‍රියාත්මක වන බව නිරන්තරයෙන්ම තහවුරු කෙරේ. මෙහිදී කිසිදු සිසුවෙකුට අවදානම් අගයන් (Risk Scores) නොපෙන්වීම දැඩිව පරීක්ෂා කෙරේ.
